Test runner for Node.js

Your Jest and Vitest tests, several times faster.

vynta runs the tests you already have, as they are: describe, it, expect, jest.* and vi.*, snapshots, module mocks, fake timers and coverage. It skips the transform pipeline, keeps its workers warm and schedules the slowest files first. It has no dependencies.

Get started Move from Jest or Vitest 
const { total } = require('./cart');
const prices = require('./prices');

jest.mock('./prices', () => ({ priceOf: jest.fn(() => 10) }));

describe('cart', () => {
  it('adds the prices of its items', () => {
    expect(total(['apple', 'pear'])).toBe(20);
    expect(prices.priceOf).toHaveBeenCalledTimes(2);
  });

  it('is empty at first', () => {
    expect(total([])).toEqual(1);
  });
});
import { describe, expect, it, vi } from 'vitest';
import { total } from './cart.js';
import { priceOf } from './prices.js';

vi.mock('./prices.js', () => ({ priceOf: vi.fn(() => 10) }));

describe('cart', () => {
  it('adds the prices of its items', () => {
    expect(total(['apple', 'pear'])).toBe(20);
    expect(priceOf).toHaveBeenCalledTimes(2);
  });

  it('is empty at first', () => {
    expect(total([])).toEqual(1);
  });
});

How it works

Nothing to rewrite: vynta understands the tests, the imports and the configuration of Jest and Vitest.

  1. 1

    Install it

    One package, no dependencies. Node.js 22 or later, which also runs your TypeScript tests without a build step.

  2. 2

    Run your tests

    npx vynta finds your test files and reads your Jest config if you have one. Globals, jest.*, vi.* and imports from vitest all work.

  3. 3

    Get the time back

    The same results, in a fraction of the time: 2.7 times faster than Vitest and 5.5 times faster than Jest on the suite we measure.

Why vynta

Most of the time a test runner takes is not your tests. vynta removes that time.

No transform pipeline

Jest runs every file through Babel, Vitest through Vite. vynta loads them with Node.js itself, including TypeScript. The only transform, hoisting vi.mock(), runs only on the files that mock.

Warm workers, real isolation

Workers stay alive between files and keep node_modules loaded. Your own modules are loaded fresh for every file, so tests do not leak into each other.

The slowest file first

vynta remembers how long each file took, starts the slowest ones first and uses just enough workers for the slowest file to be the whole run.

The APIs you know

Every Jest matcher and the Vitest ones, jest.fn, vi.spyOn, test.each, test.extend fixtures, expect.soft, expect.poll and the test context.

Snapshots and module mocks

.snap files of Jest and Vitest, inline snapshots written into your code, jest.mock and vi.mock in CommonJS and ES modules, __mocks__ and automock.

Coverage without instrumenting

V8 counts what runs, so coverage costs little. The same text table and lcov.info as Jest, with collectCoverageFrom and thresholds.
